# Baseline logging capability manifest

Issue: [#2](https://github.com/Arenoros/ulog/issues/2)

Parent roadmap: [#1](https://github.com/Arenoros/ulog/issues/1)

This manifest inventories observable logging capabilities at the immutable
userver revision recorded in [the migration baseline](baseline.md). It maps
those capabilities to the native Ulog design; it does not require source,
namespace, type, ownership, or implementation parity.

All paths prefixed with `userver:` below are repository-relative paths in the
local userver reference tree at commit
`72e07f717ae46a17822776df21ebd73dbc4ce728`. A symbol plus such a path is a
stable source citation because the revision is immutable. Tests are cited only
when they make an otherwise implicit observable contract explicit; production
source remains the owning evidence.

## Ownership and verification rules

- **Ulog core** owns dependency-light native call-site behavior, structured
  records, text encoders, built-in local/network sinks, routing, statistics,
  and runtime lifecycle.
- **Optional Ulog package** owns capabilities that require a substantial
  optional protocol or symbolization dependency, currently OTLP and
  stacktraces. Core exposes only the dependency-free seam needed by the
  package.
- **Downstream userver adapter** owns component configuration, dynamic config,
  HTTP handlers, task/span context, testsuite capture, userver value types, and
  userver metrics/signals. The dependency direction is userver to Ulog, as
  required by [ADR 0001](../adr/0001-keep-ulog-independent-from-userver.md).
- A **golden** check means a committed, platform-normalized expected result
  consumed by regular Ulog tests. The pinned userver tree may be used manually
  or in an explicitly external migration job to produce or review that result,
  but it is never a Ulog build input, package requirement, submodule, or regular
  test fixture.
- An **adapter integration** check runs in downstream userver. It may compare
  the old and new backends there; it must not add userver to Ulog's build or
  test graph.

The IDs in this file are permanent. If a capability is split later, retain its
ID as a parent and add suffixed IDs instead of renumbering unrelated entries.
